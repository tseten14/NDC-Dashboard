PART A — NON-TECHNICAL OVERVIEW
--------------------------------

A1. WHAT THIS PROJECT IS
  A web-based decision-support cockpit for Uganda’s NDC and related national
  strategies. It links targets, activities, observed emissions-style signals,
  progress indicators, and climate risk in one workspace.

A2. DATA SOURCES
  • Observed emissions: Climate TRACE (live via Express, using API v7)
  • NDC targets: Uganda Updated NDC, September 2022 (bundled in frontend/src/data/uganda-ndc-data.ts
    and config/ndcTargets.js). All sector numbers, conditionality, and BAU references are from
    the official MWE submission to UNFCCC.
  • NDC strategies: bundled in the application
  • Policy documents: Climate Policy Radar CSV export → data/policy/documents.json
    (~207 Uganda rows: laws, executive plans, UN submissions, multilateral fund projects).
    Metadata and CPR/PDF links only — no live CPR API yet. Rebuild with npm run build:documents.
  • Climate risk (illustrative): district hazard layers in the repo — not operational models
  • Delivery activities: saved in the user’s browser (localStorage)
  • Mitigation economics (Climate Finance): indicative costs/abatement from NDC catalogue — not audited
  • CPR passage corpus: Climate Policy Radar passage export for key national documents
    (NDC, NDPIV, NBSAP, etc.) — built with npm run build:passages; searchable topics/passages
  • MCF project corpus: multilateral climate fund projects — built with npm run build:mcf
    (~167 Uganda-linked projects in data/policy/mcf-projects.json)

  Note on versions: the application uses Climate TRACE API v7. "v7" is the API
  version (which endpoints exist), NOT the data version. Climate TRACE updates the
  underlying data monthly (latest release v5.8.0) and the API always serves the
  latest data. To avoid confusing users, on-screen tags simply read "Climate TRACE"
  (no version number).

A3. USERS
  Ministry staff, MRV focal points, programme managers, and executive briefings
  (role switcher in the UI — local permissions only; no remote sign-in).

A4. NATIONAL VS DISTRICT VIEW  (plain-language guide)
  On the main NDC dashboard there is a "Geography" switch with two choices:

    • National  — emissions for the whole of Uganda (data from 2015 onward).
    • District  — emissions for one selected district (data from 2021 onward).

  How to use it:
    1. Click "District".
    2. Pick a district from the drop-down (e.g. Kampala, Wakiso, Gulu).
       Kampala is selected for you by default.
    3. The charts update to show that district's observed emissions.
    4. Click "National" at any time to return to the whole-country view.

  56 Uganda districts are available. They come straight from Climate TRACE,
  which publishes district-level data using "GADM" map areas.

  IMPORTANT — what district numbers do and do NOT mean:
    • The numbers show OBSERVED emissions in that district (what satellites and
      models estimate is actually happening).
    • Uganda's NDC TARGETS are national. There is no official target for each
      district. So in District view the app shows emissions "for context" only
      and does NOT give a district a pass/fail "on-track / off-track" score.
      A short note on screen explains this.
    • Some places you might expect (e.g. Fort Portal, Entebbe, newer districts
      like Mityana) are part of a larger parent district in the map data, so
      they appear under that parent (e.g. Fort Portal → Kabarole).

A5. HOW ACCURATE ARE THE NUMBERS?
  The dashboard does not invent or guess figures. Every emissions value is the
  live figure from Climate TRACE, converted only from tonnes into million
  tonnes (MtCO2e). We checked this carefully:
    • The SIX sectors shown (AFOLU, Energy, Transport, IPPU, Agriculture, Waste)
      plus a small "mineral extraction" amount add up EXACTLY to Uganda's national
      total reported by Climate TRACE.
    • Each district's total matches Climate TRACE's own district total exactly.
  Note: the app compares these observed numbers to Uganda's NDC 2022 policy targets.
  NDC targets use national GHG inventory scale; Climate TRACE uses satellite/model
  data. These will differ — where they diverge significantly the app shows a clear
  warning. This is a planning tool, not official MRV.

  Important framing: Uganda's NDC 2022 uses BAU-relative targets ("X% below 2030
  Business-As-Usual"). Because Uganda's economy and emissions grow, the NDC 2030
  target for growing sectors is HIGHER than the 2015 actual baseline. The progress
  % on the dashboard therefore measures "how close observed emissions are to the
  NDC ceiling" rather than "how far emissions have been reduced from 2015". This is
  by design and is explained in the sector scope notes on screen.

A5b. TOP EMITTING SOURCES (asset-level drill-down)
  The NDC dashboard has a "Top Emitting Sources" panel. It lists the biggest
  individual emitters for whatever geography you are viewing (national or a
  district) — for example a named power station, or a county's forestry/road/
  building emissions. This comes from Climate TRACE's source-level data.
  IMPORTANT: these listed sources do NOT add up to the dashboard total. Climate
  TRACE also includes "spatially-uncertain" emissions (it knows the amount but not
  the exact location), which are in the total but not tied to a single listed
  source. The panel says this on screen so the headline total is never misread.

A6b. INTENDED VS MEASURED OUTCOMES (important for briefings)

  The app separates three ideas that stakeholders often conflate:

    INTENDED OUTCOMES     — NDC targets, health/air-quality goals, policy aims (left column;
                            pathway diagram on /documents; indicator panel for non-CO2 metrics)
    DELIVERY / PROGRAMMES — Activities and mitigation options in the NDC catalogue (dialogs on
                            Dashboard; indicative costs in Climate Finance)
    MEASURED OUTCOMES     — Climate TRACE observed emissions (centre column, Map, AI 2030 history)

  The urban transport "intervention pathway" on Policy documents is an ILLUSTRATIVE theory of
  change (interventions → attributes → behaviour → activity shift → outcomes). It explains
  logic; it does not attribute tonnes of CO2 to each policy instrument. Measured transport CO2
  remains on the Dashboard.

A6c. POLICY DOCUMENTS (/documents)

  Tab "Document library":
    • Filter by Category: UN Submissions, Executive, Legislative, MCF (multilateral climate funds), Reports
    • Search by title or summary; open Climate Policy Radar (CPR) or hosted PDF
    • "Analyse" button on each row → opens /documents/view in a split-pane with AI Policy Assistant
    • Result: fast access to national evidence for meetings (Bonn, MRV, finance)

  Tab "Key documents (CPR)":
    • Searchable passage corpus from Climate Policy Radar export (NDC, NDPIV, NBSAP, etc.)
    • Passage list hidden until user searches or selects a topic — avoids overwhelming empty browse
    • Results grouped by document with preview + "See all" link to full passage list
    • Topic labels deduplicated at build time (npm run build:passages); topic IDs not shown in UI
    • API: /api/v1/documents/passages/search, /documents/topics, /documents/:id/passages

  Tab "Climate fund projects":
    • Searchable MCF corpus (~167 projects) from npm run build:mcf
    • Sector-filtered links from Climate Finance MCF panel
    • API: /api/v1/documents/mcf/search, /documents/mcf/meta, /documents/mcf/:projectId

  Tab "Intervention pathway":
    • Six-column diagram (urban transport example from NDC Align / data-driven transitions materials)
    • "Related documents" on an intervention jumps to library search
    • Link to Dashboard Transport sector for measured emissions

  Policy Document View (/documents/view):
    • Stacked vertical layout: document metadata preview on top; AI Policy Assistant below (draggable divider)
    • Metadata panel shows title, date, source, category, summary — "Type" field removed
    • AI Policy Assistant uses OpenAI GPT-4o-mini via REST (routes/policyAi.js): resolves contentUrl
      from catalog catalogId when needed; fetches and parses the actual PDF, smart-truncates to
      8,000 chars (first 70% + last 20%), calls GPT-4o-mini, returns structured JSON analysis
      with real page citations [p.N]
    • Each AI bullet = 2 sentences: key fact + plain-language explanation for non-specialists
    • Quick-action buttons (2×2 grid): Executive Summary, Key Items, Targets, Actions
    • "Ask the document" free-form chat: PDF text sent to OpenAI; responses grounded in the real document
    • Requires OPENAI_API_KEY on the API server

  Dashboard "Official sources" panel (right column): small curated list per sector from
  data/policy/curated.json (NDC, BUR, flagship GCF projects, sector plans).

A6e-NEW. NDC AI (Dashboard dialog)

  Open from the "NDC AI" button on /dashboard — Perplexity-style analysis of the current
  dashboard view (selected target, sector, geography, live Climate TRACE + NDC context).

  How it works:
    • Client builds a fact_ledger (frontend/src/lib/dashboard-ai-facts.ts) from live dashboard
      data before each request — every quotable number has an id, value, claim, and verified URL
    • POST /api/v1/dashboard/analyze (routes/dashboardAi.js) sends context + fact ledger to
      OpenAI GPT-4o-mini; model may only quote numbers from quotable_facts
    • Backend attaches citations deterministically: fact ids → Climate TRACE API endpoints or
      UNFCCC NDC PDF URLs; numeric claims in each paragraph matched to ledger entries
    • Per-paragraph inline citation pills (e.g. climatetrace, unfccc +1) link to the exact source
    • Requires OPENAI_API_KEY on the API server; responses cached ~30 minutes

  Quick actions: Progress check, Gap vs pledge, Sector emissions, Top priorities.
  Free-form chat: Ask about NDC progress vs Climate TRACE for the selected target.

  Not: a web search engine, forecasts, or official UNFCCC submission text. Citations point to
  Climate TRACE v7 API URLs (api.climatetrace.org/v7/...) and the Uganda NDC 2022 PDF on UNFCCC.

B2a. DISTRICT MAPPING + DATA ACCURACY
  • config/ugandaDistrictGadm.js — maps 56 Uganda districts to Climate TRACE
    GADM level-1 ids (+ aliases for spellings/towns). Refresh/verify with
    `node scripts/discover_uganda_gadm.mjs`.
  • Sector → Climate TRACE slug mapping lives in config/ndcTargets.js. All 10
    Climate TRACE sectors are accounted for (updated per NDC 2022 — Transport
    is now a separate dashboard sector):
        AFOLU       = forestry-and-land-use
        Energy      = power + buildings + fossil-fuel-operations   ← excl. transport
        Transport   = transportation                               ← new sector (NDC 2022)
        IPPU        = manufacturing + fluorinated-gases
        Agriculture = agriculture
        Waste       = waste
        (mineral-extraction is reconciliation-only, not a UI card)
  • National reconciliation: sum of all slugs == Climate TRACE country total
    (delta 0). District totals use Climate TRACE's exact all-sector total.
  • Subnational data starts 2021; national starts 2015. Latest inventory year capped at
    2025 in config/climateTrace.js (CT v7 March 2026 dataset confirmed through 2025).

    t8:  CSA adoption 31.7% (2020) → 70.7% est. by 2030
    t9:  Wetlands coverage 8.9% (2020) → 12% by 2030  [new]
    t10: Electricity access 24% (2020) → 75% by 2030  [new]

  Agriculture is retained as a CT-observed card but has no standalone NDC 2022
  mitigation target; agricultural measures (agroforestry, livestock, irrigation)
  are sub-components of the AFOLU sector target.

B2b. ASSET/SOURCE-LEVEL DATA + GADM LEVELS
  • GET /api/v1/emissions/sources wraps Climate TRACE GET /v7/sources for the
    active geography (national or district), paginated by limit/offset. Backed by
    fetchSources() (config/climateTrace.js) + cached getSources()
    (services/climatetrace.js). Verify shape with `node scripts/verify_sources.mjs`.
  • Rows mix individual assets (e.g. power stations) and GADM aggregations
    (forestry, buildings, agriculture, roads). The "Top Emitting Sources" panel
    surfaces them, sorted by emissions.
  • GADM levels for Uganda: level-0 = country (UGA); level-1 = districts (our
    geography selector); level-2 = counties / city councils (appear as named rows
    in the sources panel, e.g. "Kampala City council", "Bokora County").
  • /v7/sources/emissions is the "Aggregate Emissions" endpoint and accepts all
    three GADM levels; its totals INCLUDE spatially-uncertain emissions. Located
    /v7/sources rows do NOT (verified Kampala 2024: aggregate 1.59 Mt vs sum of
    located rows 0.88 Mt; ~45% is spatially-uncertain). Therefore dashboard/district
    totals always come from /sources/emissions, and the sources panel is never summed.

B5. MULTI-COUNTRY NDC TRACKING (FOUNDATION + DESIGN PROPOSAL)
  Background: Climate TRACE suggested that, because NDC targets are often
  structurally similar across countries ("reduce sector X by N% below BAU by year
  Y"), the tool could track many countries from one parameterized system.

  Implemented foundation:
  • config/measurableVariables.js — a country-agnostic catalog of MEASURABLE
    VARIABLES (e.g. "Forestry & land-use emissions", "Transport emissions",
    "Renewable energy share"). Each variable records whether Climate TRACE can
    measure it directly and from which sector slugs (climate_trace.trackable +
    sector_slugs). Six emissions variables are now trackable (AFOLU, Energy,
    Transport, IPPU, Agriculture, Waste); share/capacity variables (forest cover,
    electricity capacity, CSA adoption, wetlands, electricity access) are flagged
    not directly trackable.
  • config/ndcTargets.js — each Uganda target now carries a `variable_id` linking
    it to the catalog (additive; NDC_TARGETS stays backward-compatible).
    Transport is a new sector entry (split from Energy per NDC 2022).
  • COUNTRY_NDC_TARGETS / buildCountryTargets() express Uganda on the new schema
    and compute reduction_pct + Climate TRACE trackability per sector.

  Proposed follow-up (not yet built):
  1. Add a country registry (COUNTRY_NDC_TARGETS) entry per country with its own
     per-sector NDC parameters (baseline year/value, target year/value, condition).
  2. Parameterize the API/UI by country (gadmId), defaulting to Uganda, so the same
     dashboard serves Kenya, India, etc. once their parameters are entered.
  3. Drive a "what we can / cannot track" view directly from the trackability map,
     making coverage explicit per country.
  Effort note: this requires per-country NDC parameters and Climate TRACE baselines;
  it is a phased product expansion, not a one-line config change.
