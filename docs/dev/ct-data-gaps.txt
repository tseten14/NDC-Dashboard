Uganda NDC Data Explorer — Application Data Gaps & Climate TRACE Requests
================================================================================
Document date: 22 May 2026
Project: Uganda NDC Data Explorer (national MRV cockpit prototype)
API in use: Climate TRACE API v7 (https://api.climatetrace.org/v7)
            NOTE: "v7" is the API version (endpoints/features), NOT the data version.
            The API always serves the latest data release (monthly; latest v5.8.0,
            May 2026). User-facing "Climate TRACE v7" tags were removed (June 2026) so
            users are not shown an API version where they expect a data version.
Contact context: UN / University of Melbourne collaboration; demo 17 June 2026

This file lists (A) known limitations in our application when using Climate TRACE,
and (B) requests to the Climate TRACE team that would improve accuracy and fitness
for NDC / national MRV dashboards like ours.


PART A — PROBLEMS AND LIMITATIONS IN THE APPLICATION
====================================================

1. NDC BASELINES VS CLIMATE TRACE OBSERVATIONS (NOT AN API BUG)
   - Uganda NDC targets use policy / national-inventory-style BAU baselines.
   - Climate TRACE uses satellite + model-based national totals (co2e_100yr).
   - Progress percentages can look misleading even when API data is correct.

   Example (Uganda, 2023):
   - Energy:    NDC baseline 6.2 MtCO2e  vs  TRACE observed ~14.15 MtCO2e
   - AFOLU:     NDC baseline 42.5 MtCO2e vs  TRACE forestry-and-land-use ~32.46 MtCO2e
   - Agriculture: NDC baseline 28.4 MtCO2e vs TRACE agriculture ~44.03 MtCO2e

   The app currently plots TRACE observed values against NDC baseline/target lines.
   This is intentional for the prototype but must be explained in demos and reports.

2. INCOMPLETE TARGET COVERAGE (4 OF 8 NDC TARGETS NOT FROM TRACE)
   Live Climate TRACE data backs only national MtCO2e-style trajectories:
   - t1 AFOLU emissions (MtCO2e)
   - t4 Energy emissions (MtCO2e)
   - t6 Waste emissions (MtCO2e)
   - t7 IPPU emissions (MtCO2e) — partial (see item 3)

   These targets still use bundled / ministry-style indicator data (not TRACE):
   - t2 Forest cover (% land area) — needs EO / National Forestry Authority
   - t3 Renewable energy share (%) — needs MEMD / UERA statistics
   - t5 Transport modal shift (%) — needs Ministry of Works and Transport MRV
   - t8 Climate-smart agriculture adoption (%) — needs MAAIF programme data

3. SECTOR MAPPING MISMATCHES (SCOPE, NOT FETCH ERRORS)
   - AFOLU dashboard sector maps only to TRACE slug "forestry-and-land-use".
     It does NOT include the agriculture slug (by design, to avoid double-counting
     with the separate Agriculture NDC target). This is narrower than full IPCC AFOLU.
   - IPPU maps only to "manufacturing". HFC / fluorinated-gases and other IPPU
     categories are not included in the IPPU dashboard bucket.
   - "Energy" sums power + transportation + buildings + fossil-fuel-operations.
     This is broader than a narrow NDC "energy sector" inventory line.
   - mineral-extraction (~0.04 MtCO2e nationally in 2023) is not assigned to any
     dashboard sector; country ranking total is ~0.04 Mt higher than our sector sum.

4. DISTRICT-LEVEL EMISSIONS NOT IMPLEMENTED
   - UI supports National / District geography toggle.
   - Emissions API returns national data only; district_unavailable flag is set.
   - v7 supports GADM-based queries (/v7/sources, /v7/sources/emissions) but our
     Express layer does not yet aggregate district timeseries for Uganda districts.

5. PROGRESS METHODOLOGY VS OFFICIAL MRV
   - Progress % = (NDC_baseline - TRACE_latest) / (NDC_baseline - NDC_target).
   - Official Uganda MRV may use different years, gases, sectors, or LULUCF rules.
   - Dashboard is an "observed emissions layer + NDC strategy shell", not BTR/CRT.

6. COMPARISON TO OTHER INVENTORIES
   - TRACE Uganda total (~100.6 MtCO2e, 2023, co2e_100yr) differs substantially
     from EDGAR-style national GHG totals (~53 MtCO2e, 2023) due to methodology.
   - Fossil CO2-only inventories (~8 Mt, 2023) are lower than our "energy" bucket
     because TRACE energy includes transport, buildings, etc.
   - Users may perceive TRACE as "wrong" when it differs from EDGAR/GCP; need
     clear provenance labels (partially implemented in UI).

7. API USAGE CONSTRAINTS WE WORK AROUND
   - Repeating query parameter sectors=power&sectors=transport returns ONLY the first
     sector (verified). We issue one request per sector slug and sum client-side.
   - Comma-separated sectors= works for aggregation but we use per-slug calls for
     clarity and cache granularity.
   - Missing slug for a year → entire UI sector year is null (strict mode; avoids
     under-counting partial energy totals).

8. NON-EMISSIONS DASHBOARD LAYERS (OUT OF TRACE SCOPE)
   - NDC activities: browser localStorage (demo persistence).
   - Risk choropleth: bundled placeholder geometries / seed scores.
   - Strategy library, mitigation options, catalog activities: static bundled data.
   - QA/QC "validated" flags: largely static; not tied to live TRACE QA endpoints.

9. DATA FRESHNESS AND YEARS
   - latestInventoryYear() assumes current calendar year may be incomplete.
   - Some sectors have sparser years than others; charts show gaps (no interpolation).
   - 2025 country totals exist in v7; completeness varies by sector slug.

10. DEMO / ENGINEERING DEBT
    - No automated regression tests against TRACE reference totals in CI.
    - Cache TTL 1h per slug; stale banner may show "cached" for rankings (24h).
    - No user-facing "Data coverage" panel yet explaining items 1–3 above.


PART B — REQUESTS TO CLIMATE TRACE (FOR GREATER ACCURACY & NDC FIT)
===================================================================

Reference: v7 docs https://api.climatetrace.org/v7/docs/index.html
Verified reconciliation (Uganda 2023): country ranking 100.62 Mt vs sum of 8 sector
slugs 100.58 Mt (delta ~0.04 Mt = mineral-extraction not in our map).


A. NDC / NATIONAL INVENTORY ALIGNMENT
-------------------------------------
REQ-01  Publish NDC-relevant sector groupings or mapping tables
        Provide documented mappings from TRACE sector slugs to IPCC 2006 categories
        and common NDC sector labels (AFOLU, Energy, IPPU, Waste, Agriculture) with
        guidance on avoiding double-counting when agriculture is reported separately.

REQ-02  Optional "national inventory alignment" layer
        Where TRACE differs from UNFCCC / EDGAR / national BUR figures, expose:
        - official national total when available (with source year)
        - TRACE total
        - documented adjustment factors or scope notes per sector

REQ-03  Separate LULUCF / forestry flux reporting
        For forestry-and-land-use: distinguish emissions vs removals (net vs gross)
        and flag years dominated by land-use change vs stable forest, to align with
        AFOLU targets that reference deforestation / afforestation narratives.

REQ-04  BAU / reference pathway metadata per country
        If TRACE cannot supply NDC baselines, publish recommended reference years
        and sector scopes so dashboards do not mix incompatible baseline years.


B. API DESIGN & AGGREGATION
---------------------------
REQ-05  Reliable multi-sector aggregation in one request
        Support either:
        - comma-separated sectors= that always returns the UNION sum, or
        - explicit sectors=all_no_forest (documented) with per-sector breakdown in
          totals.summaries without requiring N parallel calls per year.

REQ-06  Country + sector annual endpoint optimized for dashboards
        e.g. GET /v7/countries/{gadmId}/emissions/annual?start=&end=&gas=
        returning all sectors in one payload (tonnes + MtCO2e + metadata).

REQ-07  Document behaviour of repeated query parameters
        OpenAPI should state that duplicate sectors= keys use first value only, to
        prevent integrator under-counting or over-counting.

REQ-08  Include mineral-extraction and other minor sectors in sector enumerations
        So national sector sums reconcile to country ranking within rounding.


C. GEOGRAPHY (DISTRICT / SUBNATIONAL)
--------------------------------------
RESOLVED (2026): District drill-down is now wired in this explorer.
        Uganda districts map to Climate TRACE GADM level-1 areas (e.g.
        "Kampala District" = UGA.16_1), discovered via
        GET /v7/admins/UGA/subdivisions. 56 districts are mapped in
        config/ugandaDistrictGadm.js (the 2 non-district level-1 areas,
        Lake Albert and Lake Victoria, are excluded). Refresh/verify with
        scripts/discover_uganda_gadm.mjs.
        Caveats observed:
          - Subnational (level 1/2) emissions are only available from 2021
            onward; country level (UGA) goes back to 2015.
          - Several post-2010 districts (e.g. Mityana, Bududa, Manafwa) and
            towns (Fort Portal, Entebbe) have no distinct GADM level-1 area;
            they alias to their GADM parent district in the config.
          - NDC targets are national; district observed emissions are shown
            for context only, not as district-level NDC compliance.

REQ-09  Standardized GADM2 (district) annual totals for Uganda
        Document supported gadmId formats for Uganda districts and provide
        bulk annual emissions by district + sector for dashboard drill-down.

REQ-10  Rate limits and bulk download guidance for subnational warming
        Clear quotas / batch endpoints so national MRV systems can pre-warm
        district caches without hundreds of thousands of asset-level calls.


D. GAS, METRIC, AND UNCERTAINTY
-------------------------------
REQ-11  Document co2e_100yr vs other GWPs in API responses
        Include gas definition, GWP source (AR5/AR6), and whether totals are
        gross emissions or net (especially AFOLU).

REQ-12  Uncertainty intervals per country-sector-year
        Even coarse confidence bounds would let dashboards show QA/QC states
        instead of binary "validated / not validated".

REQ-13  Versioned dataset releases
        Expose dataset_version or release_id on responses so dashboards can pin
        reproducible snapshots for BTR reporting cycles.


E. NON-EMISSIONS INDICATORS (LINKED TO TRACE WHERE POSSIBLE)
----------------------------------------------------------
REQ-14  Crosswalk to activity / outcome indicators
        Where TRACE assets support derived indicators (e.g. renewable share proxy,
        forest extent proxy), document limitations vs ministry statistics.

REQ-15  Power sector disaggregation
        Separate grid vs off-grid, renewable vs fossil if available, to support
        NDC targets on renewable energy share (t3) alongside MtCO2e (t4).


F. QUALITY, PROVENANCE, AND SUPPORT
---------------------------------
REQ-16  Machine-readable provenance block on every aggregate response
        Fields: methodology, spatial resolution, temporal resolution, last_updated,
        data_sources[], known_limitations[], citation string.

REQ-17  Changelog / migration notes v6 → v7 → future
        Stable deprecation windows; sector slug rename alerts.

REQ-18  Sandbox or sample national package for Uganda
        Curated JSON/API examples matching v7 docs for demo integrators (UGA 2015–
        latest, all sectors, rankings, one district sample).

REQ-19  Support channel for MRV integrators
        Technical contact for sector-mapping questions affecting national dashboards.


PART C — WHAT WE HAVE VERIFIED (INTEGRATION IS CORRECT)
=======================================================
- Per-slug fetches match v7 /sources/emissions totals (tonnes → MtCO2e).
- Sum of 8 mapped slugs ≈ country ranking (±0.04 Mt, 2023).
- Dashboard API reproduces same numbers as direct v7 calls.
- We do NOT forward-fill missing years (gaps remain null).
- Energy sector requires all four slugs present before summing a year.


PART D — RECOMMENDED DEMO TALKING POINTS
========================================
1. "Observed layer = Climate TRACE (satellite + models, co2e_100yr); data updates monthly."
2. "Targets / baselines = Uganda NDC policy text — not recalibrated to TRACE."
3. "Four targets use ministry-style indicators until national feeds are connected."
4. "District emissions and official inventory reconciliation are planned extensions."


PART E — JUNE 2026 CLIMATE TRACE FEEDBACK: CHANGES MADE
=======================================================
The Climate TRACE team reviewed the prototype and sent feedback. Actions taken:

E1. API VERSION vs DATA VERSION (RESOLVED)
    Clarification from CT: the "v7" in the API URL is the API version (which
    endpoints/features exist), not the data version. The API always serves the
    latest data release (monthly cadence; latest is v5.8.0). There is not yet an
    endpoint that returns the data version number.
    Action: removed user-facing "Climate TRACE v7" tags across the UI, exports,
    lineage, and API data_source strings; these now read "Climate TRACE". The
    internal API version constant (CLIMATE_TRACE_API_VERSION = "v7") and the
    api_version field on health/snapshot responses are kept, since they correctly
    describe the API.

E2. RATE LIMITS (RESOLVED / INFORMATIONAL)
    CT confirmed the API is NOT rate-limited. Our per-slug fetch fan-out and
    node-cache layer remain for latency/cost, not to dodge quotas. (Our own
    express-rate-limit middleware protects OUR endpoints; it is unrelated to CT.)

E3. ASSET / SOURCE-LEVEL DATA (IMPLEMENTED)
    CT pointed to GET /v7/sources?...&gadmId=...&limit=&offset= for source-level
    data. Implemented:
      - config/climateTrace.js fetchSources() + zod schema (climateTrace.schema.js)
      - cached service getSources() in services/climatetrace.js
      - GET /api/v1/emissions/sources route (national + district, via resolveGeography)
      - frontend emissionsApi.sources() + "Top Emitting Sources" panel in the NDC Layer
      - scripts/verify_sources.mjs (live-shape check)
    Each row mixes individual assets (e.g. "Mutundwe power station") and GADM
    aggregations (forestry, buildings, agriculture, roads), sorted by emissions.

E4. DISTRICT-LEVEL / GADM2 / AGGREGATE EMISSIONS (INVESTIGATED — NO CHANGE NEEDED)
    The v7 endpoint set (from /v7/docs/openapi.json) is: /admins[/:id[/subdivisions]],
    /cities, /definitions/*, /owners, /rankings/countries, /sources, /sources/:id,
    /sources/emissions. The "Aggregate Emissions" endpoint the team referred to is
    /v7/sources/emissions, which accepts GADM level 0, 1, AND 2 and which we already
    use for national and district totals/timeseries.
    Key finding (Kampala, 2024):
      - Aggregate /sources/emissions total:        1,594,784 tCO2e (1.59 Mt)
      - Sum of located /sources rows:                880,986 tCO2e (0.88 Mt)
      - Spatially-uncertain (in aggregate, not in located rows): 713,798 tCO2e (44.8%)
    Implication: district totals MUST come from /sources/emissions (which include
    spatially-uncertain emissions) — they do (getLocationTotalMt). The Top Emitting
    Sources panel lists located sources only and is explicitly labelled as NOT
    summing to the dashboard total.
    GADM levels for Uganda: level-1 = districts (our selector); level-2 = counties /
    city councils (surfaced as named rows in the sources panel). For Kampala, level-1
    total == level-2 total (single subdivision UGA.16.1_1), confirming exact
    reconciliation. No change to the district data path is required.

E5. MULTI-COUNTRY NDC TEMPLATING (FOUNDATION + PROPOSAL)
    Gavin's idea: a catalog of measurable variables (e.g. "Reduction in
    forestry-and-land-use emissions below BAU") that any country parameterizes
    (Uganda 22%, Kenya 30%, etc.) so one tool tracks many countries.
    Action: added config/measurableVariables.js (variable catalog + Climate TRACE
    trackability map) and expressed Uganda's existing targets on it
    (backward-compatible with NDC_TARGETS). Full multi-country onboarding (per-country
    NDC params + CT baselines for other nations) is proposed as a follow-up; see the
    "Multi-country NDC tracking" design notes in PROJECT_DOCUMENTATION.txt.

E6. DATA INGESTION (PRODUCT DECISION — NOTED)
    CT noted automatic insights on unformatted data are hard, and that we must choose
    rapid-automatic (user formats data to a strict schema) vs slow-manual feedback.
    Our ingestion already uses a strict column-mapping/validation step (rapid-automatic
    path). No code change; captured here as a documented product decision.

E7. ACTIVITIES & MITIGATION OPTIONS — DUMMY-DATA AUDIT (June 2026)
    Audit of the "Activities / Measures" and "Mitigation Options" panels (NDC Layer).
    These panels are served by the bundled catalog API (/api/v1/catalog/activities,
    /api/v1/catalog/mitigation-options), backed by config/ndcCockpitCatalog.js, with
    frontend/src/data/uganda-ndc-data.ts as the offline fallback. Climate TRACE does
    NOT provide activities, mitigation measures, focal points, costs, or case studies,
    so the catalog (derived from Uganda's Updated NDC, Sept 2022) is the only source.

    Fields REMOVED (fabricated / unverifiable, not in the NDC or any API):
    - Activities: named focal points + email addresses (e.g. "Dr. Sarah Namirembe /
      s.namirembe@mwe.go.ug") and the "Notify focal point / Compose email" mailto flow.
    - Activities: assumed per-activity district lists. Districts are now kept ONLY where
      the NDC explicitly names locations — Greater Kampala BRT (a7: Kampala, Wakiso,
      Mukono) and Green Cities (a8: Kampala, Gulu, Mbarara, Hoima, Mbale). Other
      activities are shown as national-scope (no fabricated district pinning).
    - Mitigation: foreign "best practice" case studies with specific outcome stats
      (e.g. "Costa Rica forest cover 21%->52%", "Durban 7.5 MW / 340 ktCO2e/yr").
    - Mitigation tab DISPLAY: cost badges ("USD 15 million") and confidence badges
      ("Medium confidence") are no longer shown in the panel.

    Fields KEPT (NDC-traceable) and how they are now sourced:
    - Activity/measure name, description, responsible ministry/department, target &
      sector linkage  -> catalog body (Uganda Updated NDC 2022). Shown as-is.
    - Mitigation abatement potential -> shown explicitly labelled "(indicative)" with a
      footnote stating it is a sector-level NDC estimate, not a measured value.
    - "Captured" activities in the Activities panel come from real user/MRV DB records
      (use-captured-activities) and are unchanged.

    Graceful fallbacks added: activities show "Named focal point not available in the
    NDC source"; mitigation shows "Abatement: data not available" when no estimate
    exists; both panels carry a "Source: Uganda Updated NDC (Sept 2022), via catalog
    API" footnote.

    RESIDUAL / UNRESOLVED limitation: indicative costEstimate / costMagnitude /
    confidence values still exist in the catalog body because the Climate Finance
    screening tool consumes them (clearly labelled "indicative screening, not investment
    advice" there). They are NOT shown in the Activities/Mitigation tabs. Recommended
    follow-up: have Climate Finance derive cost-to-abate from a transparent $/tCO2e
    assumption instead of per-measure capex, so these unsourced figures can be removed
    entirely.
